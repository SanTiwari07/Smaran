## Partial-snapshot mirror refresh (Qdrant Server → Qdrant Edge)

Qdrant's documented sync path, run against the real server on a separate collection: restore a full snapshot of shard 0 into an Edge Shard (2,000 points), add 20 points on the server, then refresh the Edge Shard with a partial snapshot built from its manifest.

| | Bytes | Time |
|---|---|---|
| Full snapshot (initial restore) | 5,103,104 | 54.44 s |
| Full snapshot after the additions | 5,144,576 | |
| **Partial snapshot (refresh)** | **5,122,048** (99.6% of full) | 41.19 s |

- Mirror after refresh: 2,020 points, server: 2,020; newest point searchable on the Edge Shard: yes. Consistent.
- Measured result: at this size the partial snapshot is about as large as a full one. The refresh is correct, but it saved no bandwidth here, also with the server optimizer settled before each snapshot and with a lower indexing threshold (tried, not kept). We report it as measured.
- Not the live Agora path: the demo mirror refreshes from the change feed, which sends only changed points (see the module docstring).
